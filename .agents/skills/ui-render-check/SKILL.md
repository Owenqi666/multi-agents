# ui-render-check

单元测试测不出重叠、裁切、暗色下看不清这类问题。改完画面就截图，自己看过再说完成。

## 运行

先把页面跑起来（样张不需要服务；经由桥时看 `frontend/README.md` 的开发模式），再在另一个终端截图：

```bash
cd frontend && corepack pnpm specimen
```

```bash
cd frontend && node ../.agents/skills/ui-render-check/scripts/shot.cjs http://127.0.0.1:5173/specimen.html /tmp/ui-shots
```

脚本要能 `require('playwright')`。`frontend` 还没有把 Playwright 列进依赖时，用 `NODE_PATH` 指向一份已装好的 Playwright 和对应的 Chromium，不要为截图改 `package.json`。

脚本做的事：

- 亮色 1280 px、暗色 1280 px、亮色 400 px 各渲染一次，开减少动效，所以截到的都是落定状态。
- 页面有 `window.stage.goto(i)` 时，截第一步、第 6 步（盲审）、第 7 步（返工汇合）和最后一步；`--beats 0,3,5` 可以换。
- 再开动效截一张交接进行中的画面 `motion-midflight.png`。
- 打印每次渲染的横向溢出像素和控制台错误，最后一行是 `CHECK: ok` 或问题数，有问题时退出码为 1。

## 看图

脚本只能查溢出和报错，美观要靠看。用读图工具打开截图，至少看：

1. 亮色和暗色的盲审那一步：两位审核者、隔断、快照标签有没有挤在一起。
2. 400 px 的任意一步：字是否不小于 11 px，有没有被裁掉，控件是否还在一屏内好按。
3. 动画进行中那一张：移动的标签是否压住了文字。

问自己：一眼能看出谁在工作、刚从谁手里交过来吗？暗色是认真设计过的，还是反色？有没有一个元素是多余的？

发现问题先改，再跑一遍。同一个问题改了三轮还在，就停下来把截图和现象报告给用户。

## 不要做

- 不要只看 `CHECK: ok` 就说画面没问题。
- 不要为了让脚本通过而隐藏溢出的内容；溢出说明布局在窄屏下没有重排。
- 不要把截图提交进仓库，放在临时目录。
