# handoff-stage

舞台是给使用者看的：一眼看出现在是哪个模型在干活，工作刚从谁手里交过来，交的是什么。美术效果优先，但画面要克制。它只读运行状态，不发任何动作，所以怎么改都不影响后端运行。

## 舞台上有什么

只有四样东西，别的都不放：

1. **角色**：你、工作台，以及运行状态里出现的模型（Astra、Fable、Sol、Opus、Terra、Sonnet）。名字用文字，标记用简单几何形，不画任何公司的标志。
2. **交接**：一件带标签的东西（目标草稿、任务卡、候选、快照、阻塞意见）从交出者移动到接手者。交接是整个画面唯一的主动画。
3. **说明**：当前阶段、一句大标题、一句话说明、谁在工作、谁交给谁。
4. **进度**：已完成、当前、未开始各是什么样，静止时也能读懂。

表格、图表、侧栏、日志、diff 都不上舞台，它们在详情页。

## 数据

画面由一份故事数据驱动：`frontend/src/stage/story.ts` 定义形状，`frontend/src/stage/derive.ts` 从读回换算。

```ts
Holder = { key, family: 'claude' | 'gpt' | 'human' | 'system', tone, name, sub, role, reported*, requested* }
Beat   = { id, step, title, phase, holders: Holder[], fork: 'blind' | 'parallel' | null, carry, note }
Story  = { beats: Beat[], phases: Span[], loops: Span[] }
```

步骤、持有者和完成标志按 `docs/web-api/contract-2026-11-19.md`「接力线的步骤和数据来源」的 12 步表换算（T-0069 交付后以 `docs/project-service.md` 为准），换算说明写在 `frontend/README.md`。

规则：

- **模型名只写后端报告过的。** 站点和说明里的模型名只取 `evidence.reported_*`、`runtime.reported_*` 或审核席位 `attempts[].reported_*`；为 null 时写「未确认」，请求值另外标「请求」，不拿来顶替。不要按预设表猜。
- **作业运行期间不读抢锁的记录。** `task`、`task-test`、`task-review`、`integration`、`stage`、`plan` 以及它们的 diff 和日志在作业期间不读；舞台按作业的 `action` 判断交接物停在哪一步，审核席位读不抢锁的 `review`，作业结束后再整体刷新。
- **步骤数不是常量。** 只画有记录的步骤。单席审核只画一条线，没有返工就没有回环，直接模式没有合并和接受。画面从 `beats` 生成，不能假设固定步数或固定两个审核者。

## 画面规则

- **颜色按模型家族分。** Claude 三个模型同一暖色相的三个深浅，GPT 三个模型同一冷色相的三个深浅，你用正文墨色（暗色里是白光），工作台用安静的钢灰。颜色跟着席位：报告值能认出时按报告值，否则按请求值，只用来区分席位，不当作模型证据。状态色（通过、失败、要处理）和角色色分开，只用在徽标和 diff 上。
- **静止可读。** 已完成的步骤看得出做完了，当前步明显突出，未来的步骤淡但在。截图、缩略图、减少动效时都靠这一点。
- **一次只有一个动作。** 交接动画 0.8 到 1.2 秒，缓入缓出，落定后才高亮接手者。其他元素只做淡入淡出，不加漂浮、闪烁、粒子。
- **盲审要画出来。** 同一份快照同时交给两位审核者，两条支线之间有一道写着「互不可见」的隔断，返工时合回同一个实施者，线下方用虚线标出「返工后回到测试」。分派阶段的并行子卡也分支线，只标「并行」，不画隔断。
- **两套主题都要设计过。** 亮色和暗色各自成立，不是简单反色。
- **窄屏不横向滚动。** 改竖排，或只让画面本身在自己的容器里滚动。画面里的字不小于 11 px。
- **减少动效。** `prefers-reduced-motion: reduce` 时不自动播放、不做动画，直接显示每一步的落定状态。

## 选定的样张：接力线，精致写实

2026-11-18 做了织带、接力线、圆桌三版，选定接力线（[样张](https://claude.ai/artifact/Ffw4NxMRSpNCaD4Qe2FrT4)，共享文件夹 `multi-agent/stage-samples/relay.html`），风格按 `relay-refined-style-draft.html` 改为精致写实。落在 T-0070 的第 0 步样张 `frontend/specimen.html` 上，以 Owen 在样张上的确认为准（见 `frontend/README.md`「样张确认」）。

材质：暗色为主。底板是深色玻璃，细边，淡网格。已完成的一段是带微光的细线（细芯、柔和的光晕、一道高光），未开始的一段是刻在底板上的浅槽。交接物是带指示灯的玻璃小胶囊。亮色是同一块底板印在细纸上的图纸：墨线，没有光晕，槽是压印的。阶段用图纸上的尺寸线标在线的上方。

## 控件

`上一步`、`播放 / 暂停`（最后一步时显示`重播`）、`下一步`，加一个可点击的步骤刻度。打开时自动播放，每步约 3.5 秒，到最后一步停。键盘左右键切步。组件对外暴露：

```js
stage.goto(i)   // 立即显示第 i 步的落定状态，截图检查用
stage.play()
stage.pause()
```

## 做之前、做之后

1. 先读 `frontend-design`，写出颜色、字体、布局的小方案，再动手。
2. 改完用 `ui-render-check` 截图，至少看第一步、盲审、返工汇合、最后一步，亮色、暗色和 400 px 宽各一遍，再看一张动画进行中的截图。
3. 看图时问自己：交接是否一眼可见，有没有重叠、裁切、挤压，暗色是否同样好看，画面是否安静。有问题先改再交。
