# T41：单次规划执行控制器

本卡将已冻结的一个规划 attempt 连接到实际预检、模型事件、资源结算和 T40 证据封存。每次只执行一个新 stage/attempt，不自动重试或派发实现。正常流程依次执行 Claude draft、Codex review，再由既有 T40 helper 核验并原子绑定任务。

开工 HEAD 与最终卡片基线均为 `644d70ccdcbaf30bea043113cd7500976eed70fe`。T40 正常提交及钩子通过后才派发本卡，`--dispatchable` 通过，范围内无基线差异。原始用户需求为：“新开一个阶段2窗口开始按开发顺序继续执行”。

Claude 文本复核实际报告 `claude-opus-5-5`，completed、exit 0；请求 high，实际 effort 未确认。四项意见分别处理为：等 T40 实际提交后锁定基线；所有所依赖 public API 不足时退回规划；同时发生 caller 取消和宿主故障时明确异常优先级；缺失或 false 的停止核对都持续阻塞，不提供自动解除。原始输出在外部 `card-reviews/T-0041-runner-draft/`，处置及派发回执在 `T41/`。

## 实现边界

新 `planning_runner.py` 使用数据库父目录的协作锁，扫描同库所有未 bound 的 managed Prepared 尝试。只执行本次持锁期间新准备的 context，旧停止未知阻止 prepare/spawn。每个 attempt 使用一个新 RuntimeAdapter；预检和模型共用 T39 的固定 deadline，schema 从本次冻结文件读取，权限为 READ_ONLY。

真实环境、模型报告、terminal 和 ProcessExited 保持原值；宿主解析和证据失败不改写实际模型结果。完整资源结算后调用 T40 seal，再按实际 receipt 写 Reconciled，最后才校验草案或复核。review 之前核验当前 draft manifest，成功后仍通过 T40 的精确来源 CAS 绑定。详细顺序与限制见 [单次规划运行器](../planning-runner.md)。

取消期间独立 consumer 继续 drain，controller 的重复取消不关闭它。取消回调先保存内存接受事实，再写数据库；写失败仍禁止 validation。允许一次有界补写同一原意图，但先检查是否已提交，且始终保留首异常。数据库无法保存停止时，下次仍保持未知阻塞。

原需求的实现执行、独立测试、同提交审核、一次返工和用户 CLI 均由后续卡连接。本卡不改 adapters/core/store/T40 文件、旧 fake 模式、真实 fixture、协议快照、检查或受保护配置；没有新增状态、事件、失败分类或 SQL 迁移。实际产品模型及权限验收仍待 S9。

## 独立审查与故障回归

源审补齐了五处边界：没有实际退出的 `adapter.cleanup_incomplete` 只记 Diagnostic，保持取消及停止未知；冻结 schema 的 FIFO 替换必须非阻塞拒绝；submit_turn 之后消费 task 创建失败仍通过原 public events 迭代器完成取消和 drain；停止监控及其子 waiter 异常在 seal/validation 前处理；普通非终态事件在提交后抛错时按完整原 envelope 核对历史，避免补写成第二次实际报告。

持续取消意图写库失败时仍独立保存真实 ProcessExited，不补模型成功或停止事实。预检 TIMEOUT 用实际 fake 进程进入挂起和清理后再控制事件循环时钟，检查晚取消不增加预检 task 的 cancelling 计数；这是离线顺序证据，不是性能测量。FIFO 回归保留真实管道，并以独立救援线程解除未来非阻塞标志回归可能造成的同步阻塞；正常路径要求不使用救援。普通同内容消息的测试明确注入第二条 normalized synthetic 事件，不声称原始 fake wire 曾报告两次。

源文件尚未创建时的接口检查为 ImportError，只记接口 red。首批 smoke 4 项及首轮完整 runner selector 56 项通过；补充用例与最终结果另由原始日志记录。静态初轮错误涉及新增文件的捕获范围、类型和格式，按实际接口修正，没有放宽检查或旧断言。

最终完整五步通过：2044 个单元测试、30 个回放，lint/format/typecheck 全通过。新 runner 测试共 63 项；最后补充的正常事件提交不确定性与固定时间重复报告共 6 项定向通过，source 修复先于这些新用例落盘，不宣称行为 red。所有 scope 检查均为卡片中的六个新文件。
