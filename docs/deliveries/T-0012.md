## 验收对应

1. `RuntimeAdapter` 实现既有统一接口，只有只读配置，每个 session 只接受一轮。`start_session` 不启动进程；`submit_turn` 启动独立 CLI 进程。Codex 使用只读 sandbox、never approvals、ephemeral；Claude 使用 safe mode、Read/Grep/Glob、无会话持久化，并移除两个 API 凭据环境变量。fake executables 核对 argv/RPC、只读参数、环境与新会话。
2. 两边协议依据本机快照和录制。Claude 根据 `is_error` 与 `terminal_reason` 区分完成、API 错误和退出码为 0 的取消；`modelUsage` 只有单一报告模型时写标量模型证据，多个报告模型保留在原始日志。Codex 根据 `turn/completed.turn.status` 判定终态。请求回显不进入实际模型/档位字段；实际档位始终未确认。录制夹具解码测试覆盖结构化完成、取消、模型错误及 Claude 登录过期。
3. 畸形输出、重复/矛盾终态、提前退出和超时在适配器边界变为 Error。终态与 ProcessExited 分开保存。首个运行时终态解除模型执行截止时间，随后使用独立宽限期收尾并检查剩余输出，防止退出前矛盾终态被忽略。Claude 可保留已报告的限流重置时间；无法确认的重试时间为空。
4. 原始 stdout/stderr、未知事件、请求配置、进程退出分别保留在每次独立的脱敏 JSONL 日志。`check_environment` 是显式的版本/登录/目录操作，失败抛 `RuntimeFailure`，其 `.event` 为归类 Error；不会提交模型回合。`EnvironmentInfo.model_efforts` 保存目录报告的档位，Claude 无目录时为空。
5. runtime 选择独立 process group。取消先 interrupt/SIGINT，之后有界 TERM/KILL；即使主进程先退出，也清理同组普通后代。probe 的 `start_new_session` 默认 False，既有检查和语义不变。复核发现的重复终态、截止时间收尾和普通孙进程风险均已纳入实现与离线测试。
