## 主要合同

调用方持有同一实际 store 和有效 common-dir lease。入口先核当前 managed 实现的停止与交付事实，再实际检查 T44 归档。freeze 使用最初完整历史的 CAS，只调用 T31 freeze 一次；Git 对象、范围和实际 digest 一致才登记 T46 候选，实际 APPLIED 与末次完整检查都成立才返回。

inspect 每次都重新核已绑定候选、原归档、实际 Git 内容及当前历史，且不写数据。已有候选不能重新 freeze，孤立 ref 不自动收养。Git 与数据库之间的失败保留原 ref 与错误；提交后异常只按一次实际历史回读说明确认情况，不伪称补偿回滚。

当前函数只服务 T46 现有实现阶段，不提前扩展测试、审核或返工状态。原 workspace/context/logs 需保留。无新状态、事件或 SQL 迁移，T31/T43/T44/T45/T46 的旧代码与旧测试均不在本卡写入范围。

独立源码审核修正了首次读取顺序：先核 ref 控制文件，再进入内部会读取 Git 的执行归档检查；首个 ref 元数据样本跨归档读取保持不变，不能接受内容相同但 inode 已换的新样本。业务数据读取后还再次核 DB 与 lease 身份。候选提交的 author/message 可含合法非 UTF-8 bytes，只有 tree/parent 字段按 ASCII 解析，内容哈希始终覆盖完整原始 bytes。
