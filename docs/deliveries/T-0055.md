# T55 审核后自动返工、复测和复审

开发基线为 `928d1096f93ae208609fea09cee45a0de45bb608`。主窗口转达用户要求：用一张功能卡打通审核发现合格阻塞后的自动一次返工、原完整测试重跑和新候选复审，完整 verify 后提交并交回主窗口验收。主窗口的原始用户消息已核对，回传明确获得授权。

## 用户可见变化

正常 `task-review run` 默认自动续接；调用方发起一次审核即可在符合现有准入条件时经历初审 → 一次原范围返工 → 新候选 → 原完整有序命名测试 → 原审核配置复审。`retry/confirm` 在本次执行后也可续接，确认轮归一到父审核。`show` 始终只读。

三个执行入口支持 `--auto-rework/--no-auto-rework`。首次 run 默认开启并记录选择；补跑和确认默认继承父审核，显式选择仅覆盖本次执行，不改写历史；旧记录缺字段保持关闭。复审新 round 关闭自动续接，失败席仍可补跑，唯一返工限制不可通过显式开关绕过。

原独立 `task rework`、`task-test run`、`task-review run` 仍可分步使用。旧分步测试仅在输入 helper 明确关闭自动，其原冻结输入、完整测试、一次预算和旧新关联断言全部保留；这是新默认行为下的兼容性选择，不削弱检查。

## 实现与证据边界

复用现有返工资格、完整来源检查点、原子唯一预留、实施预算、前端 Claude 派发、候选冻结、测试运行器和审核运行器。原审核锁释放后才续接，实际写入仍重新核来源与 CAS；显示结果不充当写权限。

复测继承原冻结 suite 的策略及全部有序 NamedCommand，按原名称、executable 和 args 重跑，不读候选新规则或补默认值。复审沿实际返工预留绑定的父审核 checkpoint 继承全部席位、模型/effort 请求、timeout/grace 和可执行文件请求字符串；后者原本没有二进制 hash，不能声称固定了相同审核二进制。

新审核保持独立 review，不使用 confirmation 关系替代返工关联。旧候选、原测试、原审核和完整历史保留；新证据绑定新的候选及尝试。返工失败、取消、宿主异常或不完整复测按原阶段语义停止；完整合格的非零测试仍可送审。二审仍阻塞时停止，不开启第二次返工。没有自动接受、合并或阶段 3。

没有新增 core 状态、事件、失败分类、SQL 表或迁移，既有转移和回放保持。实际输出和已产生证据按各阶段记录，不为收尾抹除失败。
