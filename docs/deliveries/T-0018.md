## 修复与接口

1. **P2-1：取消覆盖已完成报告。** RuntimeAdapter 在已观察运行时终态或 OS 退出时拒绝晚到取消，即使最终事件还在等待进程清理。runner 继续读取完整事件流，再做报告结构及工作目录检查；重复/矛盾终态仍失败。双审保留已完成席位，只取消仍运行的席位，补跑只请求失败席位。

   取消接口同步为 `async cancel(turn, *, on_accepted=None) -> bool`。接受判定、设置接受标记、调用同步回调都在首个 I/O await 之前完成；runner 在回调中持久化 `CancelRequested`，普通取消及异常清理使用相同路径。拒绝/重复请求返回 False 且不调用回调。接受后返回 True 不代表进程停止；回调异常和未恢复的 I/O 异常照常传播。保留原有“发送失败后尝试停止自有进程”的恢复行为：后备清理成功时仍读取真实终态/退出证据，不能凭返回值伪造停止。发送和清理同时失败时，取消意图也已经落库，状态保持 `CANCELLING`，不允许 `--recover` 把未知停止当作可重开。runner 等待已经开始的取消任务后才提交终态，覆盖取消返回晚于流结束的反向时序。

   Adapter Protocol、RuntimeAdapter、ScriptedAdapter、事件序列 conformance 说明和测试包装器已同步。没有添加 core 状态、事件、失败枚举或数据库迁移。

2. **P2-2：Codex 未知 phase 合法报告被拒绝。** 仅收集匹配线程/回合的 agentMessage，依 item/completed、turn.items 的顺序更新候选。显式 `final_answer` 优先；成功回合没有显式 final 时选最后一个省略/null phase 的消息。明确 commentary/partial_answer 不能作为最终报告；failed/interrupted 不提升候选。所有文本先检查字符串类型，选定候选后才检查非空与 JSON：未选中的空未知消息不妨碍有效 final，选中的空/畸形末项仍失败，不回退寻找早先的合法报告。runner 的完整报告 schema 校验保持。

   依据为本地 `protocol/codex/schema/v2/ItemCompletedNotification.json` 的 MessagePhase 兼容说明及 agentMessage.text 字符串定义；没有刷新协议快照。

3. **P2-3：Claude 未登录被归为未知错误。** 环境采集返回 stdout 和真实退出码，由对应命令分别校验。auth status 的退出码 0 配合法布尔 loggedIn 保持原行为；仅退出码 1 加 `loggedIn=false` 作为正常未登录结果，交由 runner 持久化 `auth_expired`，不启动 `-p`。退出码 1 加 true、其他非零退出、空/畸形 JSON、缺字段、非布尔值均拒绝；版本检查仍必须退出 0。

   未登录退出码依据为 [Claude CLI reference 的 auth status 说明](https://code.claude.com/docs/en/cli-reference)。本次没有实机执行该命令，仅用假可执行文件覆盖该分支。
