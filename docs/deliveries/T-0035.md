## 复核与实际修复

Claude 文本卡片复核记录在外部 `card-reviews/T-0035-text/`：completed、exit 0，modelUsage 报告 `claude-opus-5-5`；请求 high，实际 effort 未确认。四项意见已落实：单独的 RuntimeJSONError 与捕获顺序、128 层合同、字节 UTF-8 与字符串 surrogate 分工，以及现有 Error(None) 与日志/测试文件范围。该复核不是产品权限验收。

测试初次发现一次真实 macOS 退出竞态：Claude 假进程已经退出，killpg 短暂 EPERM 仍导致 cleanup_incomplete。保留原测试断言并修产品，仅在有限等待后确认实际 exit 且进程组消失时忽略 OS 信号拒绝。Recorder 的 PermissionError、组仍存在或不可访问、未知 exit 继续报错。

清理还区分“解析失败”和“物理停止失败”：read/wait 保留 RuntimeJSONError，terminate 只在子进程、组、watcher 和所有 reader 均确认停止后抑制同一解析错误的重复传播，其他 I/O 与停止错误不吞掉。最后补上 OS exit 与 pipe EOF 的竞态：read 等待既有有限尾部收集，不能跳过合法尾部或坏 JSON。两条 gate 同步测试先确认真实退出码 7，再释放待解析字节，不依赖 sleep 猜时序。

第一次完整检查通过 1461 单元/25 回放后，独立复核发现活进程的信号拒绝仍可在 finally 等 watcher 时无界等待。新增活 child 回归并将失败后的 watcher 收集限定在 grace 内；超时保留观察任务、未知 exit 和未停止所有权，测试恢复真实信号后清场。前次通过日志单独保留，最终结果须覆盖这一修复。
