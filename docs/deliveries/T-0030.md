模型成功终态和服务进程退出分开保存。核对实际 RuntimeAdapter 后，T30 没有采用草案中“非零exit即失败”的假设：成功后关闭AppServer也可能记录信号退出。Completed+真实负退出保留为等待交付，不将其误称最终验收；没有exit仍不能进入交付准备。后续测试执行器的测试命令exit0门槛是另一项规则。

停止未确认诊断由CLI/adapters边界分类，TaskDiagnostic只保存历史，不把 `adapter.cleanup_incomplete` 误当终态。后续实现runner须沿用既有review runner的边界过滤；本卡不声称已接入真实实现事件流。

迁移 `0003_tasks.sql` 新增 task_runs/task_attempts/task_history，旧迁移未改。TaskStore复用ReviewStore连接/迁移，在同一BEGIN IMMEDIATE内检查当前尝试、更新状态和追加历史。完整TaskInput单独保存，不用raw rules hash去重跨仓库/基线输入。读取多表采用一致事务，codec显式构造可信存储数据，错误直接抛。
