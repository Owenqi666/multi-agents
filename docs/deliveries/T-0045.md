# T45：一次 managed 实现运行器

本卡连接一次全新实现尝试的持锁准备、公共运行时调用、合作取消、真实事件持久化与一次性证据封存。运行器不自动重试或选择备选，不冻结候选，不启动测试/审核，不扩大任务范围。

## 主要合同

worker 在同一个 T43 作用域中保持 store 和 Git common-dir lease，先绑定 pristine adapter，再预检和调用一次 turn。绝对 deadline 在 bind 前固定一次；SessionConfig 的 model/effort 仍是请求，权限为 WORKSPACE_WRITE，cwd 为实际受管 workspace，prompt/schema 来自原 Prepared。

公共 events 按到达顺序持久化。取消后先 exit 再 Completed 与相反顺序的 runtime observations 可能不同，不能照搬规划运行器的终态/退出重排。只有 cleanup_incomplete 且实际 exit 尚不确定时，暂存该事件及后续顺序，待 drain/result 后确定保存 Error 或 TaskDiagnostic。

外层重复 caller cancellation 只发出 intent，worker 持续消费和结算后才重抛首取消。accepted callback 先保留原 envelope，再写数据库；提交后抛错与未提交失败通过完整 envelope 的实际出现次数区分。宿主首异常保留，不能靠忽略数据库错误让成功结果取得交付资格。

停止、最终摘要和产物资格分列。停止未知不扫描工作区；seal 只调用一次，失败不修补或重封。停止已确认但日志/context 封存失败时，可独立核原 workspace 的实际结束摘要；扫描失败保持 None，不能用初始摘要代替。数据库最终不可写时，报告持久化未完成，不宣称撤销成功。

合格执行先写实际 Reconciled，再核正向归档。scope_blocked 只按报告原文交回规划；completed 停在 awaiting_delivery。坏成功产物仅在合法阶段发 EvidenceRejected，其余保留 Diagnostic。候选、独立测试及审核编排属于后续卡。

## 实现期检查记录

首轮两 provider 的普通成功路径已通过；两个 scope 用例的初始失败来自新测试直接比较冻结后的 tuple 和原始 JSON list，已改为 thaw 后的语义比较。没有修改产品语义或旧测试。

实现期补充三项边界澄清：DB 故障后优先持久化 accepted cancel，旧 pending 普通报告仍保存原 envelope/时间、内部顺序和真实次数；预检正常返回后也必须核实际 settled/stop，未知时不启动 model；receipt 按运行操作分段，预检的 stop=true 不能证明随后 turn 已停。观察到 owner 改变会使当前停止资格失效，同一 turn 内后续 getter 单纯失败才可保留先前已确认的停止事实。

独立审核发现：未列在常见宿主错误类型中的自定义 Exception，可能在 finally 中先生成合格证据再向外抛出。修正方向是在持有 owner 的异常边界先记录首失败、完成结算，再显式重抛，同时保持 caller cancellation 的原对象和 cause；不通过扩异常类型白名单或关闭 lint 掩盖该问题。

共享夹具修复后，完整定向 99 个用例全部通过；首轮 82 failed / 13 passed 的日志保留，其中直接原因包括 69 个 Recorder.path AttributeError，以及由同一预检夹具中断导致的等待/状态断言失败。随后继续补充源码审核确认的控制事件必须 APPLIED、seal 返回 receipt 也属于最新实际样本等边界回归，随后新增 7 项回归全部通过；最终全量结果如下。
