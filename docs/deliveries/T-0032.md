## 权限与实际证据

Codex使用独立固定profile `multi-agent-owned-implementation`：系统minimal只读、拥有root可写、`.git`入口/admin/common-dir禁止访问、网络关闭。复用原私有HOME/CODEX_HOME、最小ChatGPT auth和全部严格配置/来源/requirements/账户审计，不添加legacy sandbox覆盖。已知null字段按宿主期望profile映射，额外非空字段仍拒绝。写路径策略在分配owner前校验；默认None仍为原只读策略。

Claude固定restricted、safe-mode、strict-mcp-config、acceptEdits、无权限应答、五个文件工具。首次唯一init在解码前必须报告正确cwd、版本、权限、精确tools、空MCP、空additional_directories及apiKeySource=none。schema输出还必须报告StructuredOutput。环境继续移除API_KEY/AUTH_TOKEN。报告值单独记录，不能把请求参数或init数组当作完整权限生效证明；init不是宿主许可握手，审计失败前无工具行为不能由此推出。

绑定基准只取T31已有root_identity。打开日志之前、Codex版本/配置/账号等待后及实际服务/thread/turn提交前复核root和日志位置。模型实际值、使用量、终态、OS退出仍独立；成功后的信号退出不抹改模型终态。业务保护路径仍在T31固定候选前检查，不宣称全部受runtime沙箱保护。

本机版本已核对为Codex 0.169.0和Claude Code 2.1.325，与protocol快照一致，无刷新或升级。新增配置字段出处、Write官方文档、实际init录制和已知限制逐项列于docs/implementation-runtime.md；权限组合行为状态是未确认。Claude文件工具不能运行shell/自测、删除/rename/改mode，不冒称这些能力已提供。
