## 复核与修复

真实 Claude 只读卡片复核记录在外部 `card-reviews/T-0034-text/`：completed、exit 0、modelUsage 报告 claude-opus-5-5；请求 high，实际 effort 未确认。输入为任务卡和原始用户要求，只做文本复核，不冒称读过仓库或产品实机验收。

四项意见落实到任务卡和文档：用户答案变更新建 run/input hash；固定 JSON/hash 规范及 artifact 含义；角色按运行时 provider 校验而非模型字符串前缀；列出五个回放场景，并确认迁移加载器自动发现编号 SQL，无额外登记文件。

GPT 辅助复核补齐三类来源边界：

- ready 复核仍有未决问题时进入 revision_required；模型自填 resolution 不当用户决定。绑定前所选 draft 的停止核对在 review 阶段仍可撤销许可。
- 失败后第一次提交 Validated 不能当作历史重复绕过合法转移；只有相同已验证产物的重复可只记历史。
- 发现宿主 Validated 产物可能与当前 Completed.result 不同，增加规范化草案/完整复核内容一致检查及纯状态、SQLite 回归。合法 card B 不能冒用 Completed(card A)，ready 不能替换模型 needs_revision。新测试的合成终态均使用真实形状的产物，保留原状态和历史断言。

边界测试还发现深层畸形 JSON 在格式化 jsonschema.ValidationError 时再次递归失败。新复核入口改用固定短错误分类并保留 cause；新草案 wrapper 同样收敛旧 helper 的 RecursionError。没有改旧 helper 或削弱测试。
