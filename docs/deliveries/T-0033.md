## 复核与处置

Claude 开发只读卡片复核保留四次原始输出：前两次 360 秒超时无终态；第三次正常 exit 0、is_error=false，但 result 仅为未执行的工具调用文本，没有复核结论，不作为通过。第四次使用明确的纯文本 reviewer system prompt，正常 completed/exit 0，modelUsage 报告 claude-opus-5-5；请求 high，实际 effort 未确认。有效原始结果在外部 `card-reviews/T-0033-text-review/`。仅基于提供的卡片与原用户需求复核，未声称独立访问仓库。开发只读复核授权与产品实机写权限探测分开。

有效复核的四项意见均处理：

1. 固定只导入/调用 T31/T32 私有接口，不修改范围外的原适配器、隔离或工作区服务；实际可复用，不需扩大写入范围。
2. 在任务卡及操作文档列出总状态与原生逐项状态词表；schema_version=1，passed 不表示完整权限验收。
3. 新增真实产品 Redactor 配合合成 auth 回显测试，报告/原始日志均不得保留明文；另分别篡改 sidecar dev/inode 并验证执行前拒绝。
4. 写清输出目录的规范路径/祖先 `.git` 检查，以及程序固定枚举的源码和协议 hash 范围。不把未知目录假称已登记工作树。

GPT 辅助复查发现 ToolExpectation 已冻结的 MappingProxy 不能直接交给只递归普通 JSON 容器的 Redactor，已先 thaw 再按同一规则脱敏，保持别名路径精确匹配。取消处理把 cancel、reader 和结果取回置于同一有限清理预算，仍无法确认停止时保留工作树。实际 RuntimeAdapter.result 是即时读取；不把这一加固描述成原实现必然挂起。日志读取新增普通文件/no-follow/总字节上限与重复 JSON key 拒绝。

## 逐项验收

| 卡条件 | 离线证据 |
| --- | --- |
| 默认仅准备 | prepare/main 测试禁止运行真实进程；新根、owner、hash、三 case、请求默认与覆盖；输出存在、路径别名、工作树内拒绝 |
| stale/tampered 拒绝 | 源码/协议 hash、固定 case、owner/root、计划 hash、sidecar dev/inode、请求配置、已有结果、未知 case 校验；执行前无 adapter 调用 |
| 原生产品权限/argv | 真实 T32 policy 和 `_audit_codex` 配合假 transport；仅 initialize/config/account/command，无 thread/turn；13 argv；审计/账号拒绝、正向失败、越界成功、畸形响应、中途异常与未跑项 |
| 模型证据 | 精确字节、请求/实际值分离、terminal/exit 分离；口头拒绝无效；工具 id/input/session/order/metadata 冲突，普通 is_error 不冒称权限拒绝；真实旧只读 fixture 仅供结构检查 |
| 部分结果与清理 | 控制文件篡改、停止未知、流异常、运行时取消和调用者取消均保留记录；确认停止且 T31 身份核对后才 remove；case 独立且失败也不覆盖 |
| 凭据与完整检查 | 合成 auth 值故意经 stderr 和 Recorder 输出，断言日志/报告无明文；完整 verify 与正常提交 hook 见外部回执 |

原生请求的字段依据本机 CommandExecParams/Response、AccountReadParams/Response schema；Claude 工具关联结构来自已有录制。操作范围、具体命令、模型调用数量、目录及清理限制写于 `docs/implementation-permission-probe.md`。所有新测试使用合成认证、假运行时和真实临时 Git 夹具，禁止安装的 CLI/真正原生权限请求。
