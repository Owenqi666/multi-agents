## 交付边界

`ExecutorLease.source` 是工作树根，`ExecutorLease.repository` 是 canonical Git common directory。registry 是宿主在后者保存的控制记录，不是工作树未跟踪文件，不进入源码 digest。模型仍不得改 Git metadata。业务 directory 是数据库的全新同级目录，包含 workspace、context 和 logs。

只有已绑定的当前 Claude draft/GPT review 对才能提供准备来源。边界核对 TaskInput 与持久化 provenance，并实际检查两份执行 manifest。新工作区使用原始 baseline 的对象字节，不读取当前 HEAD 或未提交改动。prompt 完整内联模型所需的原始需求、卡、规则、有序派发、用户声明和绑定信息；外部 context 仅供宿主核验。

registry 在业务资源创建前登记。它可以由持锁宿主更新观察到的身份，未知字段保留 null；它不是停止证明。context manifest 只绑定 registry 的稳定身份，不对可更新内容建立循环 hash。不可变的 prompt/schema/控制 manifest 与真实 WorkspaceRecord 一起进入 T42 的原子 reservation。

退出持锁作用域会永久使 launch 失效；已持久化的 Prepared 只能检查，不能产生新的调用资格。部分创建和提交不确定结果保留 negative marker、原异常与精确路径。T43 不额外清理；T31 自身原有的安全失败清理保持，只报告实际留下的文件。

未知残留的当前处置顺序是保留 DB、registry、root 和异常，停止继续派发，核对原 controller 的实际资源记录和文件身份。锁可取得、PID 消失或删除 marker 都不能替代停止证据。证据绑定的人工恢复入口属于后续 S8；本卡不提供从旧 Prepared 启动或删除 marker 后绕过的操作。
