## 实现与证据边界

每次 Codex 环境检查和实际审核都创建独立 HOME、CODEX_HOME 与 TMPDIR，固定使用 0.169.0 和 `app-server --strict-config`。只从官方文件登录继承必要 ChatGPT 认证：兼容缺省或 null 的 `auth_mode`、可选 `account_id`，保留 `oauth_provenance.issuer/client_id`、`login_owner_id` 与 `last_refresh`。缺失、畸形或其他认证模式明确失败；不复制用户配置、记忆或会话状态，不把 token 放进 RPC/argv，也不修改原登录材料。最小认证格式依据同 tag 的 `login/src/auth/{storage,manager}.rs` 与 `login/src/token_data.rs`。

认证写入前，对隔离根、冻结 cwd 和日志目录做 realpath 规范化与两两双向包含检查；任意重叠均拒绝。目录使用 0700，认证和配置文件使用 0600。`CodexIsolation.spawn` 在启动期间被取消时仍等待取得自有进程 handle，再执行真实终止；`terminate` 只有在实际清理成功且观察到 OS 退出后才标记停止。`cleanup` 只删除所有自有启动与进程均已确认收尾的资源。未知启动、终止失败或删除失败保留资源位置和 `cleanup_incomplete`，无 GC 自动删除；创建失败的清理错误不掩盖原认证错误。版本预检进程也参与这一归属，不能因审核 App Server 尚未赋值就伪造 cancelled 或已退出。

权限配置只有固定 profile `multi-agent-frozen-review`：冻结 cwd 的规范化绝对路径与官方 `:minimal` 可读，network 关闭，approval 为 never；不继承 `:read-only`，不授权认证、日志、其他席位或整个用户目录。`thread/start`、`turn/start` 不发送会覆盖 named profile 的旧 sandbox 字段。改变工具 cwd 不改变固定授权根。

干净 HOME 配合禁用记忆、项目指令、skills 指令/云技能、插件、MCP 入口、hooks、子代理、shell snapshot、远端 notes/history 与非审核工具的配置。关闭额外环境、时间、apps、collaboration 指令注入，并设置 `history.persistence="none"`。`skip_host_skill_discovery=true` 是补充开关；官方 contributor 仍可能要求 host discovery，不能单独把它当作禁用保证。完整键与来源见下面的协议文档和 `policy_config`。

在任何模型回合前审计实际 `config/read`：所有要求的键必须存在，类型和值严格相等（不把 bool 当数字），只接受同版本明确列出的 optional null、固定默认值及空集合；未知键即使为 null 也拒绝。原始配置层必须是唯一自有用户配置及可识别的空系统层，拒绝其他层、配置字符串、provider、MCP、额外授权或未知覆盖。随后独立请求 `configRequirements/read`，只接受字段存在且实际为 null；空对象、缺字段或任何对象都不代表没有隐藏 requirements。

最终策略**没有 `forced_login_method`**：该字段会让服务端即使没有 requirements 文件也投影出登录限制对象，而投影又不能证明不存在其他隐藏 requirements，因此不为这个对象开例外。订阅约束改由最小认证材料与环境检查、实际运行各自的 `account/read` 验证，模型请求前要求 `account.type="chatgpt"`。线程 `instructionSources` 必须为空；回合前及最终流排空中发现 MCP 活动均拒绝结果。空 `instructionSources` 不是全部上下文隔离证明。

`_Rpc` 严格检查响应和服务器请求 ID，拒绝 bool、float、畸形或不匹配 ID。配置响应在落日志前按请求关联转成非敏感摘要；等待配置响应期间，错 ID、畸形消息及 stdout/stderr 文本也不保留原配置内容。已验证观察记录来自实际有效配置、实际层来源和实际 requirements，不拿请求值代替报告值。原始对象仍供验证器使用，脱敏不会修改它。认证字面值在进程启动前注册；业务报告仅遮盖已注册 secret，保留合法邮箱、路径及代码引用，防止通用日志脱敏破坏引用核对。

这不是整机隔离承诺。官方 macOS `:minimal` 有系统程序、库、配置目录及设备例外；可信客户端的 `fs/readFile` RPC 不属于模型工具沙箱。普通自有进程组后代参与清理，主动脱离会话的外部进程不在保证内。无模型 canary 验证当次原生命令路径；真实模型上下文、所有工具和完整审核回合仍须后续实机复验。

## 原有测试修改原因

1. 假 Codex 版本固定到受支持的 0.169.0，并新增错误版本分支；fake 从隔离目录的真实 TOML 生成有效配置与原始层，要求 `--strict-config`、先完成配置/requirements 审计，再允许 account/model/thread/turn。完整安全 defaults/null/空集合必须与产品严格键存在检查一致；故障注入不得靠简化返回值绕过 gate。
2. 旧的 `sandboxPolicy={type:readOnly}` 断言改为不得出现旧覆盖，并增加两次配置审计断言，原因是旧覆盖会破坏 named profile。原来的只读与 argv、cwd、盲审、报告证据断言保留。
3. runtime/review 测试使用模块局部合成 auth；`FAKE_*` 仅在测试适配层或生成的 fake 脚本内传递，产品环境 allowlist 不为测试放宽。其他模块的真实性检查不继承这些测试补丁。
4. 新增版本子进程后，旧 PID/进程组断言明确选择真正的 app-server 或 Claude `-p` 进程；仍核对审核进程与后代停止。旧 `test_cancel_refuses_observed_os_exit_before_exit_event` 的门闩只暂停测试目标 exit=17，避免误暂停已新增的 version 预检。
5. secret-only 脱敏会建立新的不可变 Completed 值，因此 CompletionWindowAdapter 从对象身份比较改为 Completed 类型及完整 result 相等；仍验证已观察终态、未最终持久化且 OS 子进程仍活着的窗口。

没有删除/跳过回归或改动检查入口。独立复核由同提供方子代理完成，不称跨提供方审核。
