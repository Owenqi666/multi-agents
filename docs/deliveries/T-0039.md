# T39：预检与模型共享截止时间

RuntimeAdapter 可接收一个固定绝对截止时间，让预检与模型使用同一执行预算。清理沿用独立 grace，截止时间不平移；已观察的终态不会因后续清理跨时限而被改成 TIMEOUT。ImplementationRuntimeAdapter 透传相同参数，默认 None 保持原每操作 timeout。

## 实现边界

`deadline_at` 只接受有限非 bool 数值，非法值在任何 operation、资源或 CLI 之前 ValueError。已过期值在操作中报告 TIMEOUT，保留日志/所有权生命周期。同步 expiry guard 位于实际 spawn 及 Codex thread/turn 请求之前，独立异常不会被 `_collect` 的创建不明分支误归类。

显式 D 下，预检和 Codex 版本收集的 active I/O 与 finally 清理分开。版本清理后在下一段重新检查同一个 D，不创建新预算；最后一项预检实际结果取得后，允许清理完成再返回环境。默认 None 的旧计时路径保持，不重置原预检 timer。首次模型终态仍解除模型计时，重复终态/坏 JSON 继续处理为协议错误。

取消先接受时关闭模型 timer，同时提前安排独立停止任务；超时先确定则后续 cancel 拒绝。Codex interrupt 发送有单独 grace，避免 writer.drain 挂住。独立复核发现关闭模型 timer 后的两种新风险：停止任务失败可能留下仍等活进程的 reader；接受回调抛错可能使停止任务根本没创建。现先安排停止再调用同步回调，保留原异常；停止失败唤醒主任务进入既有清理诊断。创建中尚未返回 handle 的路径仍由 Process.start 的 shielded 所有权清理负责。

没有新的 core 事件、phase、FailureCategory、SQL、CLI 命令或权限配置。T37 的进程组/EOF/日志证据保持，原终态和实际退出字段不改。完整 planning runner 留给 T40，本卡不运行真实产品模型或权限 case。

## 验收与检查

独立 deadline 用例覆盖两家过期零 spawn、同一 D 的预检和挂起模型、版本及最终预检清理跨 D、Codex 审计到模型的请求门禁、终态后的清理与矛盾尾部、取消/超时先后、挂起 interrupt、回调异常和停止未知。两家共享 D 的集成使用真实时钟；其他顺序测试在实际 fake ready 后受控推进事件循环时钟，明确属于离线时序证据，不是运行性能测试。发送挂起与资源收尾有真实时钟的外围上限，最后均实际清场。

实现适配器新增用例使用现有 owned workspace、合成认证与假 CLI，核对精确 D、None 的原 timer、构造期拒绝、过去 D 零启动，以及原 Claude tool/Codex write profile、Git deny、网络限制和实际报告合同。原 helper 仅增加可选 deadline_at 参数，旧精确断言保留。fake CLI 仅追加独立的延迟矛盾输出模式，未改变原模式。

接口基线检查的六项失败来自旧构造器不支持新 keyword，明确不作为计时行为 red。所有原始定向、失败和完整检查日志保存在外部 `T39/`，最终候选 SHA 由 completion/commit 回执绑定。
