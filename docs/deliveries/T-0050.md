# T50 固定候选的测试执行与结果展示

开发基线：`eb1dd4590e2270f101afe699d128673397a904f7`（T49）。原需求：“新开一个阶段2窗口开始按开发顺序继续执行”。用户后续指定优先完成“候选提交→执行测试→展示结果”，然后接审核和一轮返工，保留既有检查并减少碎片化拆卡。

本卡将独立检出、命令执行、事务记录、逐命令归档和 `task-test run/show` 一起实现。最终候选 SHA、完整检查和正常提交钩子结果由仓库外 `T50/completion.json` 绑定；提交前不预填尚未产生的结果。

## 可用操作与边界

`task-test run` 读取当前已核验候选和原冻结命令 registry；用户明确给出命令名称、顺序和声明来源。它创建一次独立浅检出，顺序执行冻结的程序及参数。build 产物和 scratch/cache 可被下一条 test 使用。测试不调用模型。`task-test show` 可重新打开现存数据库，显示候选、套件状态、逐命令实际报告、退出映射和真实日志路径，并重新核验归档。

实际 CLI → 临时 Git/SQLite → 假 App Server → 两条真实小型 Python 命令 → 冷启动 show 已通过。原实现工作树及其 Git 不变；二进制输出、完整候选对象和生成物保留。阶段 2 按用户操作粗估约 70%，仍缺同候选审核、一轮原范围返工及 S9 原生权限证据。

权限配置、环境和实际版本门禁已有离线验证，不能由此宣称 macOS 原生沙箱已拒绝访问。提供独立 canary prepare/run 工具：prepare 不启动 CLI、不读认证；真实 run 仍须按 runtime-protocols 在用户终端执行已具体授权方案。本卡没有执行真实产品 CLI、模型或原生 canary，也没有生成伪装成实机的 fixture。

停止范围为 `command-request-and-owned-runtime-v1`：匹配的命令 final 与登记的宿主资源已结算。内部命令进程组、任意后代停止以及生产者 stdout/stderr EOF 均保持未知。输出只证明实际收到的 server notifications；不声称服务端未发送的输出也完整。普通 0–255（124 除外）保留 runtime-normalized 退出映射；124、-1 等歧义报告不猜超时、signal 或原始 OS wait status。

历史 attempt 可以查看持久结果，但当前归档核验入口要求当前 attempt；历史项可能显示 unverified。没有自动 resume、自动重试、审核桥接、接受或合并。

## 设计与独立复核

卡片在实际 T49 基线上完成 schema、dispatchable、ancestry、范围及共享接口检查。Claude 文字复核实际报告 `claude-opus-5-5`，终态 completed、进程退出 0；实际 effort 未报告，保留未知。四项意见已落实：固定且共享的 child scratch、宿主 deadline 早于 RPC budget、实际可执行文件与版本门禁、fake wire 对照 checked-in schema。原始输出和处理记录保留在仓库外。

独立源码复核覆盖 runner、core/store 及 CLI/context/checkout/evidence。已修复：结束记录提交后宿主报错仍可能保留成功；日志写失败后首异常被后续错误替换；传输缓存必须在解析/队列之前有界。当前选择复核保留最初历史 prefix，只允许合法 HISTORY_ONLY 后缀，不以刷新历史掩盖变化。冷 show 重新计算资格，当前 Problem/负向结算会撤销旧 positive archive 的资格。

## 验证记录

完整 `scripts/verify.sh lint format typecheck unit replay` 五步通过：lint、format（227 文件）、typecheck（81 个源文件）、3,218 unit、61 replay。UTC 2026-11-17 04:09:36.065236 至 04:28:54.842858；unit 1150.05 秒，replay 8.19 秒。正常 hook 的实际结果由仓库外 completion 回执记录。此前完成的定向验证：managed state/store 50 unit 与新增 10 replay；功能链 26 unit；四条缺 final、写失败、迟到取消、Finished 提交后失败回归；运行时及 probe 54 unit。新增 unit 共134项；新增5组 managed 场景各有core/sqlite回放，共10项，原51项回放保留。

早期失败均保留：基线新入口测试因 API 未实现而失败，未构成行为 red；新 fixture 必须先取得实现 claim 再改工作树；测试辅助 Git status 原先刷新 index，改用既有 no-optional-locks helper；身份比较误含读取会变化的 atime，现比较稳定元数据；完整 ClientRequest schema 检查发现 configRequirements/read 原先错误发送 {}，生产请求改为 null 后原断言通过；lint/type/import 问题在源码与新增测试中修正。全量检查曾发现三项旧 foreign-database 用例未经过原 PlanningStore 入口（其余3215 unit通过）；现保留原实现控制器入口，在同executor lease下用短命readonly test连接核本地库，并在准备前重核数据库身份。原三个断言及unknown-test-owner共四项定向验证通过。没有删改旧断言、增加 noqa 或放宽配置。
