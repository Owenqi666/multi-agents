# T40：规划执行证据与原子绑定

本卡把一次规划执行的实际资源、原始日志和运行事件封存为可独立核验的 manifest；绑定任务前核验当前 draft/review 两份证据，再在原事务中比较 plan hash。完整 runner、取消和预检控制由 T41 接入。

开工 HEAD 与卡片基线均为 `16a063e73154577541997c83379b240d52299217`；`--dispatchable` 通过，基线到开工 HEAD 无差异。实际路径限于卡片列出的八个文件，没有改受保护配置、adapters/core、SQL 或旧回放。

Claude 先复核完整 runner 卡，建议将证据封存与控制器拆分；随后复核本卡。两次实际 modelUsage 均报告 `claude-opus-5-5`，completed、exit 0，请求 high，实际 effort 未确认。最终复核的顺序、精确配对、失败残留与遗漏测试意见均写入卡片。原始复核在外部 `card-reviews/T-0040-text/`、`card-reviews/T-0040-evidence-text/`，处置在 `T40/review-handling.json`；未运行产品真实模型或权限探测。

## 实现与边界

`planning_evidence.py` 提供独占日志目录、单次 seal、归档 inspect 和核验后 bind。实际 adapter receipt 与 result 分开取得；进程停止、资源释放、日志完整和 EOF 四项独立记录。manifest 绑定本次冻结输入、请求、Prepared/context/owner、环境、真实 terminal/exit 和原始日志，未知报告值不从请求补齐。详见 [规划执行证据](../planning-execution-evidence.md)。

`.seal-attempt.json` 保留第一次封存的实际 receipt；失败残留不覆盖，同一 attempt 不能重封。manifest 自身限制为 16 MiB，原始日志流式核验。文件使用独占无软链打开、实际 inode、模式、大小和 hash 检查，读中变化拒绝；资格从资源事实重算，不能只信任 qualified 或 sealed 声明。根代理源审补齐 sealed 与 closed/healthy/identity/bytes/hash 的一致性，以及 marker 规范字节比较对 true/1 的区分。

`PlanningStore.create_planned_task` 新增可选 `expected_plan_hash`。比较位于原 BEGIN IMMEDIATE 内、任何绑定写入之前，来源变化全部回滚。新 bind helper 必须传该 hash，旧可信底层调用保持兼容。没有新增状态、事件、失败分类或迁移；无需为未改变的状态转移另造回放。

seal 本身不等待、signal 或写规划事件。Reconciled 由未来 runner 或明确 synthetic 的测试夹具按原 terminal/exit → seal → Reconciled → host validation 顺序写。inspect 也可检查已 bound 的归档，不接管进程所有权。Prepared 后、spawn 前崩溃仍是停止未知；本卡没有自动恢复，未来 S8 提供明确人工核对入口。

接口检查首轮在源文件尚未创建时产生 ModuleNotFoundError，明确只作为缺接口 red，不作为行为失败证据。完整日志、后续检查与候选 SHA 回执保存在仓库外 `T40/`。

首轮证据 selector 为 107 passed、2 failed：新增 synthetic receipt 声称 sealed 却缺少 byte_count/sha256，测试原先期望 false manifest，实际因原始日志元数据不一致直接 ValueError。两项新测试改为精确断言拒绝及状态不变，没有修改产品或既有断言；随后 selector 109 项通过。临时 Python 子进程用固定 argv 实际运行、退出和清场，模型产物与环境仍明确为 synthetic，其余资源故障用例也不冒称真实模型。

独立源审发现：入口检查之后、等待 adapter.result 期间若存入 EvidenceRejected，原有末次绑定比较不包含该事件，仍可能封存成功。现末次读取也明确拒绝该事件，保留 marker，不生成 execution.json。新增定向回归 1 项通过；修复先落盘，因此 `evidence-rejection-race-before.txt` 实际为 green，不声称取得该问题的行为 red。原始失败与静态修复日志均保留。

最终完整五步通过：1981 个单元测试、30 个回放，lint/format/typecheck 全通过。store 定向 93 项通过，证据 selector 109 项及新增并发拒绝 1 项分别通过；最终数字以完整检查为准。
