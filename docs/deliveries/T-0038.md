## 状态与存储

新增 `PlanningEnvironmentObserved` 和 `PlanningEvidenceRejected`，没有新 phase、FailureCategory、SQL 表结构或迁移，也没有给旧 PlanningInput、PlanningAttempt 或 Started 增添默认字段。

环境观察必须发生在当前尝试 Prepared 之后、模型事件与取消之前，保留实际 null/false；同值重复只进历史，冲突拒绝。证据拒绝仅从 awaiting_validation 转 failed，无需先取得日志或停止证明；原 Completed/result/实际 exit/报告值/reconciliation 均不改。拒绝后的同一次产物不能复活，重试仍要求真实停止及原预算。额外修复两种宿主拒绝凭相同 detail 冒充重复的问题，判重必须对应实际事件类型。

## 反馈与上下文

`feedback_for_prefix` 只选择 APPLIED 的宿主验证记录，按 review 的 draft attempt、请求 task hash 和审核 artifact task hash 找到精确草案。反馈保留原 decision，另外列出未解决的用户问题与宿主拒绝原因，不将这些文本转为 UserDecision。后来的 history-only 事件和当前 state.card 的清空都不会改写已冻结反馈。

v2 prompt、context manifest 和只读 `revision-feedback.json` 共享文件 SHA256；manifest 另绑定启动前 prefix 的长度/hash。公开 inspect 只能定位唯一、内容相同的真实 APPLIED Started，不能缺失时采用当前历史。私有 prepare 路径显式传入尚未占位的 prospective prefix。旧 v1 按保存的版本重渲染，原 manifest 字节保持；旧 v1 与新 v2 context 可以在同一 run 核对。

独立代码复核发现反馈读取继承小 manifest 的 2 MiB 上限。先用合法的大宿主拒绝原因复现 prepare 失败，再改为稳定流式 hash/size 核对；小 manifest 上限、文件身份/模式和全部历史 context 检查均保留。EvidenceRejected 不使被篡改的旧上下文获得重试豁免。
