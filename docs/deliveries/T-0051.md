## 可用操作

`task-review run/show/retry/confirm` 使用原任务数据库。审核 input v2 冻结完整原 TaskInput、准确候选、实际命名测试 manifest 和 stdout/stderr bytes；两席和后续补跑、确认均使用同一 outer input hash。普通非零测试保留负向结果，缺证据不提升为通过。创建使用现有三张审核表的一个事务，无迁移或新 TaskPhase。

操作说明见 `docs/task-reviews.md`。实际模块 CLI → T50 build/test → 双审 → 冷 show，以及失败席补跑和一次交叉确认已通过，测试未重跑，各席使用同一冻结输入。阶段 2 按实际可用操作粗估约 80%（75–85%）；剩余工作包括一次原范围返工、完整规划到交付的 CLI 流程，以及 S9 原生权限验收。开发检查与原生权限证据分别报告。

`show` 保留历史报告，重新核验当前来源才设置 `current_eligible`。旧 v1 输入、prompt、manifest 和 user_supplied 语义不改；旧执行入口拒绝 v2，旧通用 show 明确只提供历史结论。新执行入口从准备至实际审核结算持有 executor lease 和 review lock。

## 证据边界

本卡没有运行真实产品模型、CLI 或原生 probe。fake reviewer 证明编排和输入绑定，不证明模型审核质量。测试输出与停止范围仍按 T50 实际收据，任意后代停止及生产者 stdout/stderr EOF 保持未知。原生权限 canary 仍待 S9；审核完成不自动接受、合并或启动实现返工。
