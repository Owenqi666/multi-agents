## 验收对应

1. **冻结引用核对。** `check_report` 对照基线或候选侧完整源文件，检查路径、闭区间行号和完整引用行；基线删除文件仍可核对。文件缺失、二进制或 gitlink 没有文本、越界行号、引用不符、仅粘贴 diff 均保留原意见并标为 `unverified`。仅规范化 CRLF 为 LF 并忽略最终一个行终止符，不裁剪空格、缩进，不接受子串；formfeed、Unicode 分隔符等其余字符仍是原行内容，不影响 Git 行号。空引用仅能匹配一个实际存在的空行。引用核对通过不代表已经证明问题的诊断正确。
2. **有证据才评估。** 缺所选报告返回 `incomplete`，不生成整体分组。只有声明的完整必需命令集合有对应候选提交记录、没有失败或错提交记录、报告齐全且无阻塞项时才 `ready`。无测试、缺命令、错提交或仅粘贴 diff 返回 `user_decision`。完整候选测试记录包含失败时返回 `needs_rework`。全部测试证据标记 `user_supplied`，`executed_by_workbench=false`。
3. **保留独立意见和异议。** 候选重复项按侧、文件、起止行及问题类别分组，每个 `members` 条目保留 `{seat, finding}`，不做语义去重。未独立提及的席位标为 `unconfirmed`。P0/P1 是阻塞项；引用已核对的单方阻塞意见仍需返工。交叉确认的完整来源和理由保存在 `confirmations` 中；`disagree` 或 `uncertain` 的阻塞项转 `user_decision`，同意不能把错误引用变成已核实，也不能消除需要修复的阻塞项。
4. **边界校验。** `REPORT_SCHEMA` 供两种运行时共同使用。`validate_report` 拒绝缺字段、多字段、错误类型、非法严重度/侧、布尔或非正行号、逆序范围、重复 ID、空白必要文本及无法编码为 UTF-8 的字符串；接受冻结后的 Mapping/tuple 并返回独立的普通 JSON 容器。异常为 `InvalidReport(ValueError)`。唯一 ID 和行范围顺序是 schema 之外的本地语义检查，调用方须在写成功终态前执行。

## 接口与限制

- `assess` 返回 `status`、`reasons`、`missing_seats`、`reports`、`groups`、`tests`。函数会重新核对引用，不信入参中可能已有的 `reference_status`。
- `groups` 保留 `location`、`members`、`confirmations`、`independent_reports` 和 `blocking`。`independent_reports` 只描述首轮独立发现，不将后续交叉确认误记为独立发现。
- 调用方负责验证所选席位与确认来源、确认目标以及仅一轮确认限制；本卡纯汇总函数信任经过边界校验的输入。P2/P3 非阻塞意见保留但不单独阻止验收。
- 错提交记录即使与正确提交记录并存，也要求用户澄清；同一命令的后续通过记录不覆盖先前失败证据。需纠正证据时创建新的冻结输入。
