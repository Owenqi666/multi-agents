# 本地多模型工作台优化项目书

## 目标与交付

面向一位开发者使用一个本地仓库的场景。用户离开再回来，应能看到哪项工作需要决定、哪个执行者仍在工作、哪一步可以继续，并能把通过验收的结果带到实际交付中。

本轮交付 Python 后端、可供现有 Web 服务调用的接口，以及单独的[前端实施交接](workbench-frontend-handoff.md)。页面由 Claude 开发。继续使用现有 CLI 作业、Git 基线、SQLite 记录、仓库归属和归档只读约定。

2026 年 11 月 25 日，五项后端开发与主窗口审核均已完成。各模块的实测结果、已知限制和页面接入位置统一记录在[项目状态与前端交接](workbench-frontend-handoff.md#本轮后端审核记录)。

## 实施顺序

| 顺序 | 模块 | 后端交付与完成条件 |
| --- | --- | --- |
| 1 | 首页待办 | 汇集本仓库需要用户确认、处理失败或验收的工作，返回原因、对象和入口。用户能同时发现不同阶段的待办，已处理事项随状态消失。 |
| 2 | 运行进展与中断恢复 | 按作业提供最近可确认的活动、时间、已完成和未完成的执行者及恢复入口。刷新后能接上已有记录，双审恢复沿用同一快照和有效报告。 |
| 3 | 审查意见处理 | 展示同组审核意见、分歧、责任任务和返工条件。用户可以针对固定代码和意见追问，留下判断或关联修复工作。验收继续使用原有测试和审批记录。 |
| 4 | 首次接入检查 | 集中显示仓库、可选基线、CLI 登录、规则文件和已登记的测试命令，提供可预览的规则模板以及下一步操作。 |
| 5 | 验收交付摘要 | 按已接受的集成生成可复制的 Markdown，包含完整提交、目标与基线、测试、审查和证据链接，可用于 PR 或同事交接。 |

新目标的未提交草稿由前端按仓库保存在本机浏览器中，提交成功后清除。该项归入前端交接。

## 开发与校验

按表中顺序实施。优先从现有状态生成页面需要的数据，共用现有写入和校验逻辑。每个模块结束时做一轮基本校验，覆盖其正常使用路径和一个直接影响业务结果的边界。使用本地样例、临时仓库或替代 CLI，不消耗真实模型额度。

## 本轮交付落点

| 模块 | 后端入口 | 验收场景 |
| --- | --- | --- |
| 首页待办 | `GET /api/attention` | 同时列出不同阶段的待办，领取阶段、完成返工或接受候选后对应项退出。 |
| 作业进展 | `GET /api/jobs/{id}/activity` | 获取正在运行的席位动态；双审恢复时保留已有报告并沿用原快照，只补跑未完成的席位。 |
| 审查处理 | `GET /api/reviews/{id}/findings`、`POST /api/reviews/{id}/decisions`、作业 `review.followup`、`plan.create`、`GET /api/integrations/{id}/rework-eligibility` | 用户判断、只读追问、关联修复和责任归属可追溯。原轮次、快照、席位、尝试编号和意见 ID 一起标识原意见。 |
| 首次接入 | `GET /api/workspace/onboarding` | 选不同提交可见不同规则和测试配置；打开面板不会写文件或启动模型。 |
| 交付摘要 | `GET /api/integrations/{id}/delivery` | 接受前显示待验收，接受后从收据导出摘要。即使目标分支随后移动，仍能还原当时的候选、测试和审核。 |

新运行的活动记录保存在工作台私有作业目录中。审查判断、追问回答和修复计划关联使用 SQLite 第 14 版迁移。已有只读归档可以读取其来源版本支持的证据。Markdown 摘要保留完整的候选与证据标识，供复制到工作台之外使用。
